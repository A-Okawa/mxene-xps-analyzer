### Functions to keep (do not remove or weaken)
- **Provider ↔ Python validation**: component-level QC (ΔBE = Python − Provider, rel. ΔFWHM, Δarea fraction; PASS/REVIEW/FAIL/CHECK/CHECK-MISSING)
- **Role-grouped QC** and the §18.2 summary logic (grouped FAIL → error; grouped PASS with component differences → warning)
- **Identifiability warning**: area-correlation (|r| ≥ 0.8), parameters at a window edge, components < 1 %
- **Change logs**: role reclassification log (tab 2) and the starting-value/window edit log `model_overrides` (tab 3); both are also recorded in the project export
- Legacy Ti3C2Tx Excel model (exact workbook reproduction, max error 0.0)

### Scientific principles (unchanged)
- **Do not assert an absolute vacancy concentration from XPS alone.** Report only `apparent_M_deficiency_delta` (a surface-sensitive index); orthogonal evidence (ICP/EDS/STEM/EELS/XAS/EPR, etc.) is required.
- For **(Nb,Ti)2CTx**, keep these **separate**:
  1. solid-solution composition (nominal vs observed Ti/Nb fraction)
  2. selective depletion (`<M>_fraction_shift`, `<M>_retention_ratio_fractional`)
  3. apparent M-site deficiency (`apparent_M_deficiency_delta`, after carbide-C normalization; Nb+Ti is never forced to 2)
  4. termination disorder (O_disordered / unresolved O_low, O_mid)
  5. oxidation (metal_oxide, oxide_O)
- Mixed-metal O_low/O_mid stay `O_unresolved_*` and are not counted as Tx. F residue is excluded from Tx by default. Dopants are not counted toward M occupancy.

## 4. Next phase: real-data calibration

### Required input data (per sample and core level)
1. **Raw HR-XPS** spectra (BE–intensity; Ti 2p, Nb 3d, C 1s, O 1s, F 1s, Cl 2p, Al 2p, Li 1s, … plus the survey)
2. **Provider fit table** (component name, BE, FWHM, area, area %, line shape, constraints, and whether doublet areas are total or primary-line only)
3. **Fitted spectra** (exported background, each component, envelope and residual traces; native project file if possible)
4. **Measurement/fitting conditions** (X-ray source, pass energy, step, spot, charge neutralization, BE referencing method,
   sputtering yes/no and conditions, background type and endpoints, line-shape definitions, RSF set / transmission correction)

Keep real data **outside the repository** (e.g. `private/` or `real_data/`, both git-ignored). Upload it to the app at runtime only.

### Calibration procedure (handoff §33)
1. Fit the Python model over the same energy range as the provider.
2. Compare the background (Shirley implementation, endpoints/averaging).
3. Compare line shapes (pseudo-Voigt with free η vs the provider's GL/LA, etc.).
4. Compare BE/FWHM constraints (are ΔSO, area ratio and shared doublet FWHM appropriate?).
5. Compare component-level and role-grouped areas.
6. Only after that, revise QC thresholds, fit windows and RSFs **with evidence**. Record each change in the KB changelog (KB v1.3.0 or later) together with its calibration data and rationale, and add regression tests.

Assumptions to calibrate are listed in `docs/scientific_basis.md` §5. Do not change the scientific model before calibration.
